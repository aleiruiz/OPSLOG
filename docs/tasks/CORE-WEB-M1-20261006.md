Shell React con inicio de sesión, aceptación de invitación, administración de la empresa, usuarios y roles, construido solo con `@opslog/ui` y sus tokens. Las llamadas a la API pasan por puertos tipados con contratos (`apps/web/app/types.ts`); el cliente real del BFF es una tarea posterior y hoy se usa un mock en memoria con datos sintéticos.

## Alcance entregado

- **Shell** (`apps/web/app`): cabecera con empresa y usuario visibles, navegación por grupos de SPECS §8 filtrada por permisos, enlace para saltar al contenido, foco al contenido al cambiar de pantalla, título de documento por ruta. Router mínimo sobre History API (sin dependencia nueva) con `basename`.
- **Autenticación** (`apps/web/auth`): sesión reflejada del BFF (`SessionInfo`: empresa, usuario, rol, permisos; sin token), pantalla de login, aceptación de invitación (mensaje uniforme para enlace inexistente, usado o vencido; contraseña mínima de 12 caracteres), panel de sesión expirada y borradores en servidor (`useServerDraft`).
- **Acceso** (`apps/web/settings/access`): administración de empresa (perfil, MFA, inactividad; los cambios de seguridad piden motivo con `ConfirmWithReason`), usuarios (lista paginada, búsqueda, invitar, desactivar con motivo) y roles (siete plantillas de sistema de solo lectura con permisos en español, copia personalizada).
- **Rutas**: `manage_config` para Empresa, `manage_users` para Usuarios y Roles; sin permiso se muestra `UiState no-permission` sin llamar a la API y la navegación oculta la entrada. El servidor sigue siendo la autoridad: un 403 del puerto también muestra el estado sin permiso.
- **Estados**: cada pantalla de datos cubre carga, vacío, sin resultados (usuarios), error recuperable con reintento, sin permiso y sesión expirada (`ResourceView`).

## Sesión expirada y borradores

Cualquier 401 de un puerto marca la sesión como expirada. El panel de reautenticación aparece sobre la pantalla actual, que permanece montada pero `inert`, de modo que no se pierde el estado. Los borradores se guardan con un debounce de 600 ms a través de `DraftsPort` (servidor), nunca en Web Storage ni IndexedDB. Si la sesión ya expiró, los cambios más recientes viven **solo en la memoria de la página** hasta que la persona vuelve a iniciar sesión; entonces se envían al servidor. Cerrar la pestaña antes de reautenticar los pierde: la interfaz lo dice con ese alcance, no promete más. Al salir de una pantalla con cambios pendientes y sesión vigente se envían al servidor.

## Dependencias y lockfile

No se añadió ningún paquete nuevo. `apps/web/package.json` declara con las mismas versiones fijadas que ya usa el espacio de trabajo: React, React DOM, MUI, Emotion (runtime) y Vitest, Testing Library, jsdom, axe-core, `@vitest/coverage-v8` (desarrollo). El cambio en `pnpm-lock.yaml` se limita a la entrada del importer `apps/web`; `pnpm install --frozen-lockfile` pasa.

## Límites y deuda declarada

- Los puertos y el mock son tipos locales (`apps/web/app/types.ts`) sobre `Permission`, `ApiError`, `Page` y `PageQuery` de `@opslog/contracts`; no existen aún contratos de usuarios, roles, empresa ni borradores. Cuando CORE-INTEGRATE los publique, los puertos deben sustituirse por el cliente generado (CSRF, `credentials: same-origin`, cookie httpOnly en el BFF).
- Las copias personalizadas de roles solo se crean; editar sus permisos requiere un control de selección con etiqueta propia que `packages/ui` no ofrece (`DataTable` selecciona con el id de fila como etiqueta).
- `FilterBar` de `packages/ui` renderiza un `<form>` sin `onSubmit`; el shell lo envuelve (`NoSubmit`) para que Enter no recargue la página. Debe corregirse en el paquete de diseño.
- `NextStepPanel` usa un `h6` bajo el `h1` de la página (regla `heading-order` de axe, de mejores prácticas y fuera de WCAG A/AA). La prueba jsdom desactiva solo esa regla.
- El mock es en memoria: recargar la página reinicia sesión y borradores. No hay pruebas contra el BFF ni MySQL; esta tarea no valida persistencia real.
- Sin snapshots de píxeles (diferidos por FND-DS). Sin cobertura de navegadores distintos de Chromium.

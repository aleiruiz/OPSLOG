## Encargo del auditor

1. **Regresión acumulativa** sobre el SHA candidato, con MySQL 8.4 sintético desechable y Chromium: `pnpm quality`, `pnpm test:integration`, `pnpm test:fleet-integration`, `pnpm test:e2e` (incluye `e2e/maintenance-real.spec.ts` sobre la API real) y `pnpm test:visual`. Registrar la versión exacta de MySQL y que ninguna prueba MySQL aplicable se omite.
2. **Mantenimiento de principio a fin**: plan por fecha/km → alerta upcoming/due/overdue → orden preventiva única → asignación → trabajo, partes y costos → término → cierre con decisión de vehículo → avance del plan una sola vez, más correctivas, reapertura y cancelación. Comparar con SPECS §6.1 y §7 y con la necesidad operativa (BRD §9): no aceptar un CRUD desconectado como workflow.
3. **Seguridad multitenant**: aislamiento A/B en bases físicas separadas, IDs ajenos con el mismo error que los desconocidos, tenant y actor solo desde la sesión, `view_costs` en lecturas, historial y errores, alcance del mecánico (D9), atomicidad negocio + historial + auditoría + outbox, y payloads de outbox con allowlist.
4. **UX y accesibilidad**: shell → Mantenimiento, NextStepPanel con faltantes estructurados, 409 con recarga, Mis órdenes a 360 px y axe WCAG 2.1 AA con contraste.
5. **Pruebas repetidas y mutación dirigida** (ADR-0011 §3): repetir las pruebas nuevas de M3 unas tres veces y mutar solo el código crítico de seguridad (alcance por tenant, `view_costs`, CAS de versión, aprobación D20).
6. **Deuda y pendientes declarados**: valorar si bloquean G3 o pueden diferirse. Están listados en `docs/traceability/maintenance.md`: Idempotency-Key en cierre/reapertura, evidencias configurables, umbral D20 en configuración, registros de alerta en la UI y los cuatro vacíos de contrato aceptados en las auditorías de #84.
